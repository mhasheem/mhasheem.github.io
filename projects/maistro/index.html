Enhancing mAIstro

Making Small Language Models Reliable in Multi-Agent Medical AI Workflows

Abstract

mAIstro is an open-source multi-agent framework that runs exploratory data analysis, radiomic feature extraction, medical image segmentation and classification from natural-language requests. It succeeds on every task with frontier models such as GPT-4o and Claude Sonnet 3.7, but cloud-hosted models conflict with data-sovereignty rules (HIPAA/GDPR), cost a lot and add latency. When moved to locally deployable small language models such as Llama 3.1 8B or Mistral 7B, task success drops to 10 to 18%, leaving resource-constrained clinics without agentic AI.

We close this gap by targeting the root causes of small-model failure in agentic pipelines: a decoupled architecture of 13+ specialized agents; JSON-driven tool execution with schema-constrained configuration in place of fragile code generation; a four-stage optimization pipeline of context pruning, enforced chain-of-thought, constrained decoding with dynamic schema validation and parameter sanitization; agentic RAG with dynamic schema slimming over a 10,000+ line tool library; and CPU-optimized tool defaults. The result is a fully offline, privacy-preserving pipeline that reaches 91% task success across four open models on modest hardware.

The problem

Built for frontier models, broken on small ones

The original system routes every request through one Master Agent and eight sub-agents that generate Python code. Small models overflow the context, lose the thread of reasoning, invent tools and write code that does not run.

Method

Engineering reliability back in

01 · Decoupled agents

13+ agents with training and inference split apart, so no agent faces an oversized tool set that invites routing hallucinations.

02 · JSON tool execution

Schema-constrained tool calls replace generated Python, removing syntax errors and invented libraries.

03 · Four-stage pipeline

Context pruning, enforced reasoning, constrained decoding and parameter sanitization, each fixing one failure mode.

04 · Agentic RAG

FAISS retrieval with schema slimming returns only the tool documentation a step needs.

05 · CPU-aware tools

CPU-optimized defaults for PyCaret, TotalSegmentator and nnU-Net run without a GPU.

Fully offline

No patient data leaves the machine, and no cloud infrastructure is needed.
